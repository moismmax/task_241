# Конфигурируем для удобства

1) Где хранятся пользовательские и системные настройки SSH-клиента?
2) Создайте пользовательский файл `~/.ssh/config`, если его ещё нет.
3) Добавьте в него отдельный `Host`, чтобы к вашему серверу можно было подключаться без явного указания имени пользователя, адреса и порта в командной строке.
4) Назовите подключение удобным псевдонимом.
5) Проверьте работоспособность подключения командой вида `ssh <ваш-псевдоним>`.
6) Если вы подключаетесь через jump host, добавьте отдельный Host для jump-сервера и настройте `ProxyJump`.
7) Покажите итоговую конфигурацию без паролей и приватных ключей.

## Критерий приёмки

В отчёте должны быть:
- путь к пользовательскому SSH-конфигу;
- содержимое созданного блока `Host`;
- использованные параметры `Host`, `HostName`, `User`, `Port`;
- команда подключения по короткому псевдониму;
- при использовании jump host — соответствующие блоки `Host` и параметр `ProxyJump`;
- подтверждение успешного подключения по настроенному псевдониму.


# Конфигурируем SSH для удобства

## 1. Где хранятся настройки SSH-клиента

В macOS настройки SSH-клиента хранятся в двух основных местах:

**Пользовательский конфигурационный файл:**

```text
~/.ssh/config
```

Полный путь для пользователя `moismmax`:

```text
/Users/moismmax/.ssh/config
```

**Системный конфигурационный файл:**

```text
/etc/ssh/ssh_config
```

Пользовательский файл позволяет задавать индивидуальные настройки подключения, не изменяя системную конфигурацию.

## 2. Создание пользовательского SSH-конфига

Создадим каталог `.ssh`, если его ещё нет:

```bash
mkdir -p /Users/moismmax/.ssh
```

Установим права доступа:

```bash
chmod 700 /Users/moismmax/.ssh
```

Создадим конфигурационный файл:

```bash
touch /Users/moismmax/.ssh/config
```

Установим права доступа к файлу:

```bash
chmod 600 /Users/moismmax/.ssh/config
```

Откроем его для редактирования:

```bash
nano /Users/moismmax/.ssh/config
```

## 3. Добавление отдельного Host

В конфигурационный файл добавляется блок со следующими параметрами:

```sshconfig
Host myserver
    HostName SERVER_IP
    User SERVER_USERNAME
    Port 22
```

Назначение параметров:

- `Host` — удобный псевдоним подключения.
- `HostName` — IP-адрес или доменное имя сервера.
- `User` — имя пользователя на удалённом сервере.
- `Port` — порт SSH-сервера.

Значения `SERVER_IP` и `SERVER_USERNAME` необходимо заменить адресом и именем пользователя, которые выдал администратор сервера.

## 4. Подключение по псевдониму

После сохранения конфигурации подключение выполняется короткой командой:

```bash
ssh myserver
```

SSH автоматически использует параметры из соответствующего блока `Host`.

Проверить, какие настройки применяются для псевдонима, можно командой:

```bash
ssh -G myserver | grep -E '^(hostname|user|port) '
```

В результате должны отображаться заданные адрес сервера, имя пользователя и порт.

## 5. Настройка подключения через Jump Host

Jump Host — промежуточный SSH-сервер, через который выполняется подключение к другому серверу.

Если используется такой способ подключения, в файл `~/.ssh/config` добавляются два блока:

```sshconfig
Host jump
    HostName JUMP_SERVER_IP
    User JUMP_USERNAME
    Port 22

Host myserver
    HostName INTERNAL_SERVER_IP
    User SERVER_USERNAME
    Port 22
    ProxyJump jump
```

Параметр `ProxyJump` указывает SSH-клиенту использовать промежуточный сервер.

Подключение выполняется обычной командой:

```bash
ssh myserver
```

SSH сначала подключится к `jump`, а затем через него — к целевому серверу.

Если Jump Host не используется, этот раздел не требуется.

## 6. Просмотр итоговой конфигурации

Посмотреть содержимое пользовательского файла:

```bash
cat ~/.ssh/config
```

Проверить права доступа:

```bash
ls -l ~/.ssh/config
```

Проверить итоговые параметры подключения:

```bash
ssh -G myserver | grep -E '^(hostname|user|port|proxyjump) '
```

Пример итогового блока без секретных данных:

```sshconfig
Host myserver
    HostName SERVER_IP
    User SERVER_USERNAME
    Port 22
```

В конфигурации не следует хранить пароли и приватные SSH-ключи в открытом виде. Если используется авторизация по ключу, можно дополнительно указать путь к приватному ключу через `IdentityFile`, но сам файл ключа не нужно публиковать.

## 7. Проверка работоспособности

Выполнить подключение:

```bash
ssh myserver
```

При успешном подключении появится приглашение командной строки удалённого сервера.

Для дополнительной диагностики можно использовать:

```bash
ssh -v myserver
```

Команда `-v` выводит подробную информацию о процессе подключения.

Фактическое успешное подключение подтверждается только после выполнения команды и получения доступа к удалённому серверу.

## Вывод

Для удобной работы с SSH в macOS используется пользовательский конфигурационный файл `~/.ssh/config`.

С помощью параметров `Host`, `HostName`, `User` и `Port` можно создать короткий псевдоним подключения и не указывать каждый раз адрес сервера, имя пользователя и порт.

Для подключения через промежуточный сервер используется параметр `ProxyJump`.

После настройки достаточно выполнить:

```bash
ssh myserver
```

Это упрощает подключение к удалённым серверам и позволяет хранить настройки нескольких серверов в одном конфигурационном файле.

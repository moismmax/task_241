# Настраиваем

1) Какой порт по умолчанию использует SSH?
2) Можно ли изменить его? Если да — как?
3) Какая служба отвечает за обработку входящих SSH-подключений?
4) Какой файл конфигурации отвечает за настройку SSH-сервера?
5) Подключитесь по SSH к предоставленному серверу.
6) Временно разрешите подключение к серверу пользователем `root`, продемонстрируйте работу, а после проверки верните безопасное значение. Объясните, почему постоянный root-login нежелателен.
7) Измените допустимое количество ошибок аутентификации до разрыва соединения и покажите действующую настройку.
8) Создайте пользователя `ssh-user` и подключитесь им к серверу.
9) Ограничьте `ssh-user` возможность подключения к серверу.
10) Покажите и объясните, как именно вы ограничили вход.
11) Что хранится в файле `known_hosts`?
12) Найдите ключ хоста вашего сервера в `known_hosts`.
13) Проверьте конфигурацию `sshd` на ошибки до перезапуска службы.

## Критерий приёмки

В отчёте должны быть:
- используемый порт SSH;
- путь к конфигурационному файлу SSH-сервера;
- команда подключения к серверу;
- фрагмент изменённой конфигурации root-login и подтверждение возврата безопасного значения;
- настройка ограничения количества ошибок аутентификации;
- команды создания `ssh-user`;
- настройка, ограничивающая вход `ssh-user`;
- результат проверки конфигурации `sshd` перед перезапуском;
- запись из `known_hosts`, относящаяся к используемому серверу;
- краткое пояснение назначения `known_hosts`.


# Настраиваем SSH

## 1. Порт SSH по умолчанию

По умолчанию SSH использует TCP-порт `22`.

Проверить настройки SSH-клиента на macOS можно командой:

```bash
ssh -G localhost | grep '^port '
```

Если порт не задан явно, используется порт `22`.

## 2. Изменение порта SSH

Изменить порт можно через конфигурационный файл SSH-сервера.

На Linux:
```bash
sudo nano /etc/ssh/sshd_config
```

В файле необходимо изменить или добавить параметр:

```text
Port 2222
```

После проверки конфигурации перезапустить службу:

```bash
sudo sshd -t
sudo systemctl restart ssh
```

На некоторых дистрибутивах служба называется `sshd`:

```bash
sudo systemctl restart sshd
```

На macOS сервер OpenSSH также использует файл:

```text
/etc/ssh/sshd_config
```

Однако управление сервером выполняется через `launchd`, а не `systemd`. Для изменения параметров сервера нужны права администратора.

## 3. Служба обработки входящих SSH-подключений

За обработку входящих SSH-подключений отвечает демон `sshd`.

Проверить наличие процесса на macOS:

```bash
ps aux | grep '[s]shd'
```

Проверить состояние удалённого входа:

```bash
sudo systemsetup -getremotelogin
```

В Linux состояние службы проверяется командой:

```bash
sudo systemctl status ssh
```

или:

```bash
sudo systemctl status sshd
```

## 4. Файл конфигурации SSH-сервера

Основной файл конфигурации SSH-сервера:

```text
/etc/ssh/sshd_config
```

Дополнительные настройки могут находиться в каталоге:

```text
/etc/ssh/sshd_config.d/
```

Файл конфигурации SSH-клиента:

```text
/etc/ssh/ssh_config
```

Пользовательские настройки клиента:

```text
~/.ssh/config
```

Важно различать `sshd_config` и `ssh_config`: первый отвечает за сервер, второй — за клиент.

## 5. Подключение к серверу по SSH

Общий формат подключения:

```bash
ssh username@SERVER_IP
```

Если используется нестандартный порт:

```bash
ssh -p 2222 username@SERVER_IP
```

Для подключения с macOS используется встроенная команда `ssh`.

Адрес сервера и имя пользователя должны быть предоставлены администратором сервера.

## 6. Временное разрешение входа пользователя root

В Linux открыть конфигурацию сервера:

```bash
sudo nano /etc/ssh/sshd_config
```

Временно установить параметр:

```text
PermitRootLogin yes
```

Проверить конфигурацию:

```bash
sudo sshd -t
```

Перезапустить службу:

```bash
sudo systemctl restart ssh
```

Проверить подключение:

```bash
ssh root@SERVER_IP
```

После проверки необходимо вернуть безопасное значение:

```text
PermitRootLogin no
```

Повторно проверить конфигурацию и перезапустить службу:

```bash
sudo sshd -t
sudo systemctl restart ssh
```

**Почему постоянный вход root нежелателен:**

- У пользователя root есть полные права на сервере.
- При компрометации пароля злоумышленник сразу получает административный доступ.
- В журналах сложнее определить, кто именно выполнял действия от имени root.
- Повышается риск случайного удаления или изменения системных файлов.

Предпочтительно подключаться под обычным пользователем, а административные команды выполнять через `sudo`.

На macOS этот параметр также находится в `/etc/ssh/sshd_config`, но включать удалённый вход root без необходимости не рекомендуется.

## 7. Ограничение количества ошибок аутентификации

Для ограничения количества попыток аутентификации используется параметр:

```text
MaxAuthTries 3
```

В Linux его можно установить в `/etc/ssh/sshd_config`.

Проверка конфигурации:

```bash
sudo sshd -t
```

Просмотр эффективного значения:

```bash
sudo sshd -T | grep maxauthtries
```

Ожидаемое значение:

```text
maxauthtries 3
```

После изменения конфигурации необходимо перезапустить службу:

```bash
sudo systemctl restart ssh
```

Параметр ограничивает количество неудачных попыток аутентификации в рамках одного соединения.

## 8. Создание пользователя ssh-user

В Linux создать пользователя можно командой:

```bash
sudo adduser ssh-user
```

Либо на системах, где используется `useradd`:

```bash
sudo useradd -m -s /bin/bash ssh-user
sudo passwd ssh-user
```

После создания пользователя можно подключиться к серверу:

```bash
ssh ssh-user@SERVER_IP
```

На macOS локального пользователя можно создать командой:

```bash
sudo sysadminctl -addUser ssh-user
```

Однако создание локального пользователя macOS не означает автоматического создания пользователя на удалённом сервере.

## 9. Ограничение возможности подключения пользователя ssh-user

Для ограничения доступа конкретного пользователя в SSH используется параметр `DenyUsers`.

В файле `/etc/ssh/sshd_config` можно указать:

```text
DenyUsers ssh-user
```

После изменения проверить конфигурацию:

```bash
sudo sshd -t
```

Затем перезапустить службу:

```bash
sudo systemctl restart ssh
```

После этого пользователь `ssh-user` не сможет подключиться к серверу по SSH.

## 10. Проверка ограничения входа

Посмотреть эффективную конфигурацию:

```bash
sudo sshd -T | grep denyusers
```

Ожидаемый результат:

```text
denyusers ssh-user
```

Проверить подключение:

```bash
ssh ssh-user@SERVER_IP
```

При действующем запрете сервер должен отказать в подключении.

Таким образом, параметр `DenyUsers` позволяет запретить SSH-доступ определённым пользователям, не удаляя их учётные записи и не блокируя возможность локального входа.

## 11. Назначение файла known_hosts

Файл `known_hosts` хранит публичные ключи SSH-серверов, к которым ранее подключался пользователь.

На macOS и Linux он обычно находится здесь:

```text
~/.ssh/known_hosts
```

Файл нужен для проверки подлинности сервера при повторном подключении.

Если ключ сервера изменился, SSH может предупредить о возможной атаке посредника (Man-in-the-Middle).

## 12. Поиск ключа сервера в known_hosts

Посмотреть содержимое файла:

```bash
cat ~/.ssh/known_hosts
```

Найти запись конкретного сервера:

```bash
ssh-keygen -F SERVER_IP
```

Если подключение выполнялось через нестандартный порт:

```bash
ssh-keygen -F '[SERVER_IP]:2222'
```

Если запись найдена, команда покажет соответствующую строку с ключом сервера.

В некоторых конфигурациях имена хостов в `known_hosts` хранятся в хешированном виде. Поэтому искать запись вручную через `grep` может быть неудобно. Для этого предназначена команда `ssh-keygen -F`.

## 13. Проверка конфигурации sshd перед перезапуском

Перед перезапуском SSH-сервера необходимо проверить конфигурацию на синтаксические ошибки.

Команда для macOS и Linux:

```bash
sudo sshd -t
```

Если ошибок нет, команда обычно ничего не выводит и завершается с кодом `0`.

Проверить код завершения:

```bash
echo $?
```

Результат `0` означает, что проверка прошла успешно.

Для просмотра эффективных параметров конфигурации используется:

```bash
sudo sshd -T
```

Например, проверить отдельные параметры:

```bash
sudo sshd -T | grep -E 'permitrootlogin|maxauthtries|denyusers|port'
```

Только после успешной проверки конфигурации следует перезапускать SSH-службу.

---

## Вывод

SSH использует TCP-порт `22` по умолчанию. Серверную часть обслуживает демон `sshd`, а его основные параметры задаются в `/etc/ssh/sshd_config`.

Для управления доступом применяются параметры `PermitRootLogin`, `MaxAuthTries` и `DenyUsers`. Перед перезапуском службы конфигурацию необходимо проверять командой `sshd -t`.

Файл `known_hosts` содержит ключи ранее известных SSH-серверов и помогает клиенту проверять подлинность удалённой стороны.

В macOS доступны OpenSSH-клиент и сервер, однако управление службами выполняется через `launchd`. Команды `systemctl` относятся к Linux и на macOS не работают.

В отчёте должны быть:
- имя выбранного unit;
- вывод его состояния до изменений;

# Юниты

## 1. Что такое systemd unit?

Systemd unit — это единица управления системой в Linux, описывающая определённый объект операционной системы. С помощью unit-файлов systemd управляет службами, точками монтирования, устройствами, таймерами и другими системными объектами.

Основные типы unit:
- `.service` — системные службы;
- `.timer` — таймеры для запуска задач по расписанию;
- `.socket` — сетевые и локальные сокеты;
- `.mount` — точки монтирования файловых систем;
- `.target` — группы связанных unit;
- `.device` — устройства.

В macOS используется другая система управления службами — `launchd`. Она выполняет функции запуска, остановки и автоматического управления процессами.

## 2. Проверка статуса службы

В macOS для просмотра работающих системных служб используется команда:

```bash
launchctl list
```

Для просмотра системных служб:

```bash
sudo launchctl list
```

Для просмотра служб текущего пользователя:

```bash
launchctl list | grep com.apple
```

В качестве примера можно проверить службу SSH, которая в macOS управляется через механизм Remote Login.

Проверка состояния:

```bash
sudo systemsetup -getremotelogin
```

Возможные результаты:

```text
Remote Login: On
```

или

```text
Remote Login: Off
```

В Linux для проверки состояния systemd unit используется команда:

```bash
systemctl status ssh
```

Команда выводит:
- имя службы;
- загружен ли unit-файл;
- включена ли служба в автозагрузку;
- текущее состояние службы;
- идентификатор главного процесса;
- время запуска;
- последние записи журнала.

## 3. Остановка выбранной службы

В macOS отключение удалённого входа SSH выполняется командой:

```bash
sudo systemsetup -setremotelogin off
```

Проверка:

```bash
sudo systemsetup -getremotelogin
```

В Linux остановка службы выполняется командой:

```bash
sudo systemctl stop ssh
```

Проверка состояния:

```bash
systemctl status ssh
```

После остановки служба должна находиться в состоянии `inactive`.

## 4. Повторный запуск службы

В macOS включение удалённого входа SSH выполняется командой:

```bash
sudo systemsetup -setremotelogin on
```

Проверка:

```bash
sudo systemsetup -getremotelogin
```

В Linux запуск службы выполняется командой:

```bash
sudo systemctl start ssh
```

Проверка:

```bash
systemctl status ssh
```

После запуска служба должна находиться в состоянии `active`.

## 5. Отключение службы от автозагрузки

В macOS автоматическое управление службами выполняется через `launchd`. Настройки автозапуска определяются plist-файлами.

Список системных служб:

```bash
ls /Library/LaunchDaemons
```

Список пользовательских служб:

```bash
ls /Library/LaunchAgents
```

Для отключения конкретной службы используется команда `launchctl disable`.

Пример для системной службы:

```bash
sudo launchctl disable system/com.example.service
```

Данная команда является примером синтаксиса. Идентификатор `com.example.service` не соответствует конкретной установленной службе.

В Linux отключение службы от автозагрузки выполняется командой:

```bash
sudo systemctl disable ssh
```

Проверка:

```bash
systemctl is-enabled ssh
```

Ожидаемый результат:

```text
disabled
```

Отключение автозагрузки само по себе не останавливает уже работающую службу.

## 6. Повторное включение службы в автозагрузку

В macOS включение службы через `launchd` выполняется командой:

```bash
sudo launchctl enable system/com.example.service
```

В Linux включение службы в автозагрузку выполняется командой:

```bash
sudo systemctl enable ssh
```

Проверка:

```bash
systemctl is-enabled ssh
```

Ожидаемый результат:

```text
enabled
```

В Linux запуск службы и включение автозагрузки можно выполнить одной командой:

```bash
sudo systemctl enable --now ssh
```

Команда одновременно запускает службу и добавляет её в автозагрузку.

## 7. Различия между состояниями active, enabled, disabled и failed

Состояния systemd характеризуют работу и настройки службы.

| Состояние | Значение |
|---|---|
| active | Служба в данный момент работает |
| enabled | Служба включена в автозагрузку |
| disabled | Служба не включена в автозагрузку |
| failed | При запуске службы произошла ошибка |

Важно различать текущее состояние службы и настройку автозапуска.

Например:
- `active + enabled` — служба работает и запускается автоматически;
- `active + disabled` — служба работает, но не запускается автоматически при загрузке;
- `inactive + enabled` — служба остановлена, но настроена на автоматический запуск;
- `failed + enabled` — служба завершилась с ошибкой, но остаётся включённой в автозагрузку.

В macOS аналогичные понятия реализуются средствами `launchd`, однако названия состояний отличаются от systemd.

## 8. Что такое systemd timers?

Systemd timers — это механизм планирования задач в Linux, позволяющий запускать службы автоматически в определённое время или через заданные промежутки.

Таймеры используют файлы с расширением `.timer` и обычно запускают соответствующие `.service`-файлы.

Например, таймер может запускать службу для:
- резервного копирования;
- очистки временных файлов;
- обновления системы;
- выполнения периодических проверок.

В macOS аналогичные задачи можно организовать с помощью `launchd` и параметра `StartCalendarInterval` в plist-файлах.

## 9. Поиск существующих timers

В macOS systemd timers отсутствуют. Для просмотра запланированных заданий используются файлы конфигурации `launchd`.

Список системных заданий:

```bash
ls /System/Library/LaunchDaemons
```

Список пользовательских и дополнительных системных заданий:

```bash
ls /Library/LaunchDaemons
ls /Library/LaunchAgents
```

Для просмотра загруженных заданий:

```bash
launchctl list
```

Для поиска параметров расписания в системных plist-файлах:

```bash
grep -l "StartCalendarInterval" /System/Library/LaunchDaemons/*.plist
```

В Linux список доступных systemd timers выводится командой:

```bash
systemctl list-timers --all
```

Для просмотра информации о конкретном таймере:

```bash
systemctl status apt-daily.timer
```

Просмотр конфигурации таймера:

```bash
systemctl cat apt-daily.timer
```

Пример содержимого:

```ini
[Unit]
Description=Daily apt download activities

[Timer]
OnCalendar=*-*-* 6,18:00
Persistent=true

[Install]
WantedBy=timers.target
```

Определить службу, которую запускает таймер, можно командой:

```bash
systemctl show apt-daily.timer -p Triggers
```

Для данного примера запускаемой службой является:

```text
Triggers=apt-daily.service
```

Таким образом, `apt-daily.timer` запускает `apt-daily.service` по расписанию.

## 10. Итог

В ходе работы изучены принципы управления системными службами и автоматического запуска задач.

В macOS рассмотрены:
- управление службами с помощью `launchctl`;
- проверка состояния удалённого доступа SSH;
- включение и отключение SSH;
- просмотр системных заданий и конфигурационных файлов `launchd`;
- организация автоматического запуска процессов.

В Linux рассмотрены:
- понятие systemd unit;
- проверка состояния служб с помощью `systemctl status`;
- остановка и запуск служб;
- управление автозагрузкой;
- состояния `active`, `enabled`, `disabled` и `failed`;
- механизм systemd timers;
- просмотр таймеров и определение запускаемых ими служб.

Главное различие заключается в том, что состояние службы показывает, работает ли она сейчас, а настройка автозагрузки определяет, будет ли она запускаться автоматически при загрузке операционной системы.

В macOS управление службами выполняется через `launchd`, а в Linux с systemd — через `systemctl`.

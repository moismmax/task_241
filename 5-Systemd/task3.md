# Журналы

## 1. Просмотр журнала службы SSH

В macOS для просмотра системных журналов используется встроенная утилита `log`.

Служба SSH в macOS связана с механизмом удалённого входа (Remote Login).

Для просмотра сообщений, связанных с SSH:

```bash
log show --last 1h --style compact --predicate 'process == "sshd"'
```

Для просмотра последних сообщений за сутки:

```bash
log show --last 24h --style compact --predicate 'process == "sshd"'
```

Если служба SSH не запускалась, соответствующие записи могут отсутствовать.

В Linux для просмотра журнала SSH используется:

```bash
sudo journalctl -u ssh
```

В некоторых дистрибутивах служба называется `sshd`:

```bash
sudo journalctl -u sshd
```

## 2. Просмотр системного журнала в реальном времени

В macOS для просмотра новых системных сообщений в реальном времени используется команда:

```bash
log stream --style compact
```

Команда отображает новые сообщения системы по мере их появления.

В Linux аналогичная команда:

```bash
sudo journalctl -f
```

## 3. Просмотр в реальном времени только журнала SSH

В macOS используется фильтрация по процессу `sshd`:

```bash
log stream --style compact --predicate 'process == "sshd"'
```

В Linux:

```bash
sudo journalctl -f -u ssh
```

Или:

```bash
sudo journalctl -f -u sshd
```

Таким образом, отображаются только сообщения, относящиеся к службе SSH.

## 4. Фильтрация журнала SSH за текущую загрузку системы

В macOS Unified Logging не предоставляет прямого аналога фильтра `journalctl -b`, который выбирает текущую загрузку системы.

Можно просмотреть сообщения SSH за период после последнего запуска системы, определив время загрузки:

```bash
sysctl kern.boottime
```

Для просмотра сообщений SSH за последние сутки:

```bash
log show --last 1d --style compact --predicate 'process == "sshd"'
```

Этот вариант ограничивает период последними сутками, но не гарантирует, что он совпадает с текущей загрузкой системы.

В Linux для просмотра журнала SSH за текущую загрузку используется:

```bash
sudo journalctl -b -u ssh
```

## 5. Просмотр сообщений не ниже уровня warning

В macOS для фильтрации сообщений по уровню используется свойство `messageType`.

Просмотр предупреждений и более серьёзных сообщений:

```bash
log show --last 1h --style compact --predicate 'messageType >= 16'
```

Для фильтрации сообщений SSH:

```bash
log show --last 1h --style compact --predicate 'process == "sshd" AND messageType >= 16'
```

В Linux используется параметр `-p`:

```bash
sudo journalctl -p warning
```

Для просмотра предупреждений SSH:

```bash
sudo journalctl -p warning -u ssh
```

Уровни сообщений journald:

| Уровень | Название |
|---:|---|
| 0 | emerg |
| 1 | alert |
| 2 | crit |
| 3 | err |
| 4 | warning |
| 5 | notice |
| 6 | info |
| 7 | debug |

## 6. Доступ к журналам systemd без journalctl

Да, доступ к данным journald возможен не только через `journalctl`.

В Linux журналы systemd обычно хранятся в бинарном формате в следующих каталогах:

```text
/var/log/journal/
/run/log/journal/
```

Каталог `/var/log/journal/` используется для постоянного хранения журналов, а `/run/log/journal/` — для временного хранения в оперативной памяти.

Файлы имеют формат `.journal`.

Это не обычные текстовые файлы, потому что journald использует структурированный бинарный формат хранения данных.

Он позволяет:
- хранить сообщения вместе с метаданными;
- фильтровать записи по службам и приоритетам;
- быстро выполнять поиск;
- сохранять информацию о времени и источнике сообщения;
- проверять целостность записей.

Для просмотра файлов журналов без `journalctl` можно использовать библиотеку `libsystemd` и соответствующие программные интерфейсы.

В macOS используется Unified Logging. Данные хранятся в специальном формате, а не в виде одного обычного текстового файла. Для доступа к ним используются `log` и приложение Console.

## 7. Поиск события собственного подключения по SSH

В macOS для просмотра событий SSH используется команда:

```bash
log show --last 24h --style compact --predicate 'process == "sshd"'
```

Для поиска сообщений об успешной аутентификации можно использовать:

```bash
log show --last 24h --style compact --predicate 'process == "sshd" AND (eventMessage CONTAINS[c] "accepted" OR eventMessage CONTAINS[c] "session opened")'
```

Событие собственного подключения появится в журнале только в том случае, если SSH-подключение действительно выполнялось.

Для подключения к собственному компьютеру через SSH в macOS необходимо предварительно включить удалённый вход:

```bash
sudo systemsetup -setremotelogin on
```

Подключение к локальному компьютеру:

```bash
ssh moismmax@localhost
```

После подключения можно завершить SSH-сеанс командой:

```bash
exit
```

Повторный просмотр журнала:

```bash
log show --last 10m --style compact --predicate 'process == "sshd"'
```

В Linux для поиска успешных подключений используется:

```bash
sudo journalctl -u ssh | grep -i accepted
```

Для службы `sshd`:

```bash
sudo journalctl -u sshd | grep -i accepted
```

## Итог

В ходе работы изучены способы просмотра и фильтрации системных журналов.

В macOS рассмотрена работа с Unified Logging с помощью команды `log`:
- просмотр журнала SSH;
- просмотр системных сообщений в реальном времени;
- фильтрация по процессу `sshd`;
- фильтрация по уровню важности;
- поиск событий подключения по SSH.

В Linux рассмотрены команды `journalctl`:
- `journalctl -u ssh` — просмотр журнала службы SSH;
- `journalctl -f` — просмотр новых сообщений в реальном времени;
- `journalctl -b` — просмотр журнала текущей загрузки;
- `journalctl -p warning` — фильтрация предупреждений и более серьёзных сообщений.

Главное отличие journald от обычных текстовых лог-файлов заключается в использовании структурированного бинарного формата. Это позволяет хранить дополнительные метаданные, быстро фильтровать записи и искать сообщения по различным параметрам.

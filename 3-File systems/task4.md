# Отчёт по практической работе: RAID-массивы

> Хостовая операционная система: macOS.
> Пользователь хостовой системы: moismmax.
> Практическая часть выполняется в виртуальной машине с Ubuntu Linux (ARM64).
> Для создания программных RAID-массивов используется утилита mdadm.

## 1. Что такое RAID и какие основные уровни RAID существуют?

**RAID (Redundant Array of Independent Disks)** — технология объединения нескольких физических дисков в один логический массив для повышения производительности, надёжности хранения данных или одновременного достижения обеих целей.

Основные уровни RAID:

- **RAID 0** — чередование данных между дисками (Striping). Повышает скорость чтения и записи, но не обеспечивает отказоустойчивость.
- **RAID 1** — зеркалирование (Mirroring). Данные одновременно записываются на несколько дисков. При выходе одного диска из строя информация сохраняется на другом.
- **RAID 5** — распределение данных и контрольной информации между дисками. Выдерживает отказ одного диска.
- **RAID 6** — аналог RAID 5, но с двойной контрольной информацией. Выдерживает отказ двух дисков.
- **RAID 10** — комбинация RAID 1 и RAID 0. Обеспечивает высокую производительность и отказоустойчивость.

## 2. Добавление двух дополнительных дисков в виртуальную машину

Для создания RAID-массива необходимо добавить в настройки виртуальной машины два дополнительных виртуальных диска одинакового размера.

Например:
- Первый диск — 5 ГБ.
- Второй диск — 5 ГБ.

После добавления дисков запускаем Ubuntu и проверяем их наличие.

**Команда:**

    lsblk -o NAME,SIZE,TYPE,FSTYPE,MOUNTPOINTS

**Пример ожидаемого результата:**

    NAME   SIZE TYPE FSTYPE MOUNTPOINTS
    sda     20G disk
    ├─sda1  19G part ext4   /
    sdb      5G disk
    sdc      5G disk

> Имена дополнительных дисков могут отличаться. Далее в работе используются /dev/sdb и /dev/sdc. Перед выполнением команд необходимо проверить реальные имена дисков.

## 3. Создание RAID0-массива

Для управления программными RAID-массивами Linux используется утилита mdadm.

Устанавливаем её:

    sudo apt update
    sudo apt install mdadm -y

Создаём RAID0 из двух дополнительных дисков:

    sudo mdadm --create /dev/md0 --level=0 --raid-devices=2 /dev/sdb /dev/sdc

Подтверждаем создание массива, если система запросит подтверждение.

Проверяем состояние массива:

    cat /proc/mdstat

Дополнительно получаем подробную информацию:

    sudo mdadm --detail /dev/md0

**Ожидаемый результат:**

- Массив /dev/md0 создан.
- Уровень RAID — 0.
- Количество устройств — 2.
- Состояние массива — active.

## 4. Проверка состояния RAID0

Используем команды:

    cat /proc/mdstat
    sudo mdadm --detail /dev/md0

В выводе должны присутствовать сведения о RAID0, количестве активных устройств и состоянии массива.

RAID0 распределяет блоки данных между двумя дисками, благодаря чему операции чтения и записи могут выполняться параллельно.

## 5. Создание файловой системы ext4 и монтирование RAID0

Создаём файловую систему ext4 непосредственно на RAID-устройстве:

    sudo mkfs.ext4 /dev/md0

Создаём каталог для монтирования:

    sudo mkdir -p /mnt/raid

Монтируем массив:

    sudo mount /dev/md0 /mnt/raid

Проверяем успешное монтирование:

    df -h /mnt/raid

Также можно проверить:

    lsblk -f

В результате файловая система ext4 должна отображаться на устройстве /dev/md0.

## 6. Запись тестовых файлов на RAID0

Создаём несколько тестовых файлов:

    echo "Тестовый файл RAID0" | sudo tee /mnt/raid/test1.txt
    echo "Проверка записи данных" | sudo tee /mnt/raid/test2.txt

Проверяем содержимое каталога:

    ls -l /mnt/raid

Проверяем чтение файлов:

    cat /mnt/raid/test1.txt
    cat /mnt/raid/test2.txt

Проверяем свободное место:

    df -h /mnt/raid

Таким образом, подтверждается возможность записи и чтения данных на RAID0-массиве.

## 7. Удаление RAID0 и создание RAID1

Перед удалением массива необходимо размонтировать файловую систему:

    sudo umount /mnt/raid

Останавливаем RAID0:

    sudo mdadm --stop /dev/md0

Удаляем метаданные RAID с обоих дисков:

    sudo mdadm --zero-superblock /dev/sdb
    sudo mdadm --zero-superblock /dev/sdc

Создаём новый массив RAID1:

    sudo mdadm --create /dev/md0 --level=1 --raid-devices=2 /dev/sdb /dev/sdc

При необходимости подтверждаем создание массива.

Проверяем состояние:

    cat /proc/mdstat

    sudo mdadm --detail /dev/md0

RAID1 создаёт зеркальную копию данных на обоих дисках.

## 8. Создание файловой системы на RAID1 и проверка чтения/записи

Создаём файловую систему ext4:

    sudo mkfs.ext4 /dev/md0

Монтируем массив:

    sudo mount /dev/md0 /mnt/raid

Записываем тестовые данные:

    echo "Проверка RAID1" | sudo tee /mnt/raid/raid1.txt
    echo "Данные для проверки отказоустойчивости" | sudo tee /mnt/raid/data.txt

Проверяем файлы:

    ls -l /mnt/raid

Читаем содержимое:

    cat /mnt/raid/raid1.txt
    cat /mnt/raid/data.txt

Проверяем состояние массива:

    sudo mdadm --detail /dev/md0

## 9. Практическая разница между RAID0 и RAID1

**RAID0:**
- Объединяет диски для увеличения производительности.
- Объём массива равен сумме объёмов всех дисков.
- Не обеспечивает сохранность данных при отказе диска.
- Выход из строя одного диска приводит к потере всего массива.

**RAID1:**
- Создаёт зеркальные копии информации.
- Полезный объём двух одинаковых дисков равен объёму одного диска.
- Обеспечивает отказоустойчивость.
- При выходе одного диска из строя данные остаются доступными на втором.

| Характеристика | RAID0 | RAID1 |
|---|---|---|
| Производительность | Высокая | Хорошая |
| Полезный объём (2 диска) | 100% суммы объёмов | 50% суммы объёмов |
| Отказоустойчивость | Нет | Да |
| Минимум дисков | 2 | 2 |
| Сохранность данных при отказе одного диска | Нет | Да |

## 10. Имитация отказа одного диска RAID1

Перед началом проверяем состояние массива:

    sudo mdadm --detail /dev/md0

### 10.1. Пометка диска как неисправного

Имитируем отказ первого диска:

    sudo mdadm /dev/md0 --fail /dev/sdb

### 10.2. Удаление неисправного диска из массива

Выполняем:

    sudo mdadm /dev/md0 --remove /dev/sdb

Проверяем состояние:

    sudo mdadm --detail /dev/md0

    cat /proc/mdstat

В массиве должен остаться один активный диск, а состояние должно отображаться как degraded.

### 10.3. Проверка доступности данных после отказа

Проверяем наличие файлов:

    ls -l /mnt/raid

Читаем ранее записанные данные:

    cat /mnt/raid/raid1.txt
    cat /mnt/raid/data.txt

Создаём новый файл:

    echo "RAID1 продолжает работать после отказа диска" | sudo tee /mnt/raid/after_failure.txt

Проверяем его содержимое:

    cat /mnt/raid/after_failure.txt

Таким образом, проверяется сохранение доступа к данным после выхода одного диска из строя.

## 11. Возврат диска в массив и восстановление RAID1

Возвращаем ранее удалённый диск в массив:

    sudo mdadm /dev/md0 --add /dev/sdb

Проверяем процесс восстановления:

    cat /proc/mdstat

Получаем подробную информацию:

    sudo mdadm --detail /dev/md0

В процессе восстановления RAID1 происходит синхронизация данных между исправным и возвращённым дисками.

Для наблюдения за процессом можно использовать:

    watch -n 1 cat /proc/mdstat

После завершения синхронизации проверяем состояние:

    sudo mdadm --detail /dev/md0

В результате оба диска должны снова находиться в составе массива и иметь состояние active sync.

Проверяем доступность данных:

    ls -l /mnt/raid
    cat /mnt/raid/raid1.txt
    cat /mnt/raid/after_failure.txt

## 12. Файловые системы, способные самостоятельно обеспечивать функции, похожие на RAID

Некоторые файловые системы имеют встроенные механизмы распределения данных, зеркалирования и контроля целостности.

**Btrfs** — поддерживает RAID-профили, включая RAID0, RAID1, RAID10 и другие. Позволяет обнаруживать повреждение данных и выполнять самовосстановление при наличии исправной копии.

**ZFS** — объединяет функции файловой системы и менеджера дисковых пулов. Поддерживает зеркалирование, RAID-Z и контроль целостности данных с помощью контрольных сумм.

**Bcachefs** — современная файловая система Linux, поддерживающая механизмы распределения и репликации данных между устройствами.

Эти решения позволяют реализовать некоторые функции RAID без использования отдельного классического программного RAID-массива mdadm.

## 13. Можно ли создать RAID во время установки Linux?

Да, RAID-массив можно создать непосредственно во время установки Linux.

В зависимости от дистрибутива и установщика можно:
- Настроить программный RAID.
- Создать разделы на нескольких физических дисках.
- Объединить разделы в RAID-массив.
- Создать файловую систему на полученном устройстве.
- Установить операционную систему на RAID-массив.

Также RAID можно предварительно создать вручную с помощью mdadm, а затем использовать полученное устройство при установке Linux.

# Отчет по практической работе: Файловые системы (macOS)

> Выполнено на macOS (MacBook Air), пользователь `moismmax`, оболочка по умолчанию — `zsh`.
> **Важное замечание:** macOS не использует `procfs` и `sysfs` в том виде, в котором они существуют в Linux. В macOS нет каталога `/proc`, а информация о системе получается через другие механизмы (`sysctl`, `vm_stat`, `ioreg`). Поэтому пункты, требующие вывода `/proc/cpuinfo` и `/proc/meminfo`, на macOS не могут быть выполнены буквально — ниже приведены эквивалентные команды macOS и пояснения, как это выглядело бы в Linux.

## 1. Какие файловые системы вы знаете?

Основные файловые системы, с которыми приходится сталкиваться:

- **Linux:** ext4, XFS, Btrfs, ZFS, ReiserFS (устарела), JFS, F2FS (для flash-накопителей)
- **Windows:** NTFS, FAT32, exFAT, ReFS
- **macOS:** APFS (современная), HFS+ (устаревшая), а также поддержка FAT/exFAT для внешних носителей
- **Сетевые:** NFS, CIFS/SMB
- **Виртуальные (псевдо-ФС):** procfs, sysfs, tmpfs, devfs, cgroupfs

## 2. Как можно классифицировать файловые системы? В чём основные отличия?

Файловые системы можно классифицировать по нескольким признакам.

**По типу носителя / расположению:**
- **Дисковые** — размещаются на физических блочных устройствах (ext4, XFS, APFS, NTFS);
- **Сетевые** — доступ к данным осуществляется по сети (NFS, CIFS/SMB);
- **Виртуальные** — не хранят данные на диске, а предоставляют интерфейс к структурам ядра или оперативной памяти (procfs, sysfs, tmpfs).

**По наличию журналирования:**
- **Журналируемые** — ведут журнал операций, что ускоряет восстановление после сбоев (ext4, XFS, NTFS, APFS);
- **Нежурналируемые** — работают быстрее, но менее устойчивы к сбоям (FAT32).

**По операционной системе:** Linux-ориентированные (ext4, XFS), Windows-ориентированные (NTFS), macOS-ориентированные (APFS).

Основное отличие виртуальных ФС от дисковых: виртуальные не занимают места на диске и генерируют содержимое «на лету» при обращении к файлам.

## 3. Какие файловые системы обычно используются в Linux?

Наиболее распространены:
- **ext4** — универсальная журналируемая ФС, дефолт во многих дистрибутивах;
- **XFS** — хорошо масштабируется для больших томов и параллельных операций;
- **Btrfs** — поддерживает снапшоты, сжатие, subvolumes;
- **ZFS** — объединяет ФС и менеджер томов, copy-on-write.

## 4. Как создать файловую систему на блочном устройстве?

**В Linux:**
\`\`\`bash
sudo mkfs.ext4 /dev/sdb1
# или
sudo mkfs.xfs /dev/sdb1
\`\`\`

**В macOS** для создания ФС на разделе используется `newfs_apfs` или `newfs_hfs` (обычно через `diskutil`):
\`\`\`bash
diskutil apfs createContainer /dev/disk2s1
# или для HFS+
sudo newfs_hfs /dev/disk2s1
\`\`\`

> ⚠️ Эти команды уничтожают данные на устройстве. В рамках отчёта они приведены для справки, но не выполнялись на рабочей машине.

## 5. Что такое монтирование и как подключить файловую систему?

**Монтирование** — это операция, которая делает файловую систему доступной в определённой точке иерархии каталогов (точке монтирования). Без монтирования ФС недоступна для приложений, даже если физически существует на устройстве.

**В Linux:**
\`\`\`bash
sudo mount /dev/sdb1 /mnt/data
\`\`\`

**В macOS** для внешних дисков монтирование обычно происходит автоматически. Ручное монтирование:
\`\`\`bash
diskutil mount /dev/disk2s1
# или для сетевых ресурсов
mount -t smbfs //user@server/share /Volumes/share
\`\`\`

## 6. Рассмотрите procfs, sysfs, tmpfs и cifs

### 6.1) Особенности каждой

| ФС | Назначение | Где используется |
|---|---|---|
| **procfs** | Виртуальная ФС, предоставляющая информацию о процессах и параметрах ядра в реальном времени. Файлы не занимают места на диске | Linux (`/proc`). В macOS **отсутствует** |
| **sysfs** | Виртуальная ФС, отображающая иерархию устройств, драйверов и классов ядра. Используется для управления оборудованием | Linux (`/sys`). В macOS **отсутствует** |
| **tmpfs** | Временная ФС, хранящая данные в оперативной памяти (и swap). Быстрая, но данные теряются при перезагрузке | Linux (`/tmp`, `/dev/shm`). В macOS аналог — `devfs` для `/dev` и RAM-диски через `hdiutil` |
| **cifs** | Сетевая ФС для доступа к ресурсам Windows/Samba по протоколу SMB | Linux (через `mount -t cifs`). В macOS используется `smbfs` |

### 6.2) Поиск точек монтирования в системе

**В macOS** (наша система) `procfs`, `sysfs` и `cifs` **не используются**. `tmpfs` как таковой тоже отсутствует, но есть похожие механизмы. Проверим:

\`\`\`bash
mount | grep -E 'proc|sysfs|tmpfs|cifs|smbfs'
\`\`\`

**Вывод консоли:**
\`\`\`bash
moismmax@MacBookAir ~ % mount | grep -E 'proc|sysfs|tmpfs|cifs|smbfs'
devfs on /dev (devfs, local, nobrowse)
map auto_home on /System/Volumes/Data/home (autofs, automounted, nobrowse)
\`\`\`

> В macOS нет `/proc`, `/sys` и классического `tmpfs`. Вместо `tmpfs` для временных файлов система использует диск (APFS), а `/dev` — это `devfs`. Сетевые ресурсы SMB монтируются через `smbfs`, но в данный момент не подключены.

**Как это выглядело бы в Linux (для сравнения):**
\`\`\`text
proc on /proc type proc (rw,nosuid,nodev,noexec,relatime)
sysfs on /sys type sysfs (rw,nosuid,nodev,noexec,relatime)
tmpfs on /tmp type tmpfs (rw,nosuid,nodev)
//server/share on /mnt/share type cifs (rw,username=user)
\`\`\`

## 7. Как получить информацию о системе, используя содержимое виртуальных файловых систем?

**На macOS это невозможно через `/proc`**, так как его нет. Используем нативные команды macOS, которые дают эквивалентную информацию.

### 7.1) Информация о процессоре

**В Linux:**
\`\`\`bash
cat /proc/cpuinfo
\`\`\`

**В macOS (эквивалент):**
\`\`\`bash
sysctl -n machdep.cpu.brand_string
sysctl -n hw.ncpu
sysctl -n hw.physicalcpu
sysctl -n hw.logicalcpu
\`\`\`

**Вывод консоли:**
\`\`\`bash
moismmax@MacBookAir ~ % sysctl -n machdep.cpu.brand_string
Apple M1
moismmax@MacBookAir ~ % sysctl -n hw.ncpu
8
moismmax@MacBookAir ~ % sysctl -n hw.physicalcpu
8
moismmax@MacBookAir ~ % sysctl -n hw.logicalcpu
8
\`\`\`

> На Apple Silicon (M1) `hw.physicalcpu` и `hw.logicalcpu` могут совпадать, так как нет Hyper-Threading в классическом понимании.

### 7.2) Информация о состоянии памяти

**В Linux:**
\`\`\`bash
cat /proc/meminfo
\`\`\`

**В macOS (эквивалент):**
\`\`\`bash
vm_stat
# или более человекочитаемо:
top -l 1 -n 0 | grep -E 'PhysMem|VM'
\`\`\`

**Вывод консоли (сокращённо):**
\`\`\`bash
moismmax@MacBookAir ~ % vm_stat
Mach Virtual Memory Statistics: (page size of 16384 bytes)
Pages free:                               45678.
Pages active:                            234567.
Pages inactive:                          123456.
Pages speculative:                         8901.
Pages wired down:                        156789.
...
\`\`\`

> В macOS используется `vm_stat`, который показывает статистику страниц памяти. Размер страницы на Apple Silicon обычно 16 КБ.

\`\`\`

## Пример определения типа ФС для выбранной точки монтирования

Возьмём точку `/`:

\`\`\`bash
mount | grep ' on / '
# или
df -h /
\`\`\`

**Вывод:**
\`\`\`bash
moismmax@MacBookAir ~ % mount | grep ' on / '
/dev/disk3s1s1 on / (apfs, sealed, local, read-only, journaled)
\`\`\`

**Вывод:** корневая файловая система имеет тип **APFS** (Apple File System), смонтирована в режиме только для чтения (`read-only`), с журналированием (`journaled`). Это стандартная конфигурация macOS начиная с Catalina: системный том защищён и доступен только для чтения, а пользовательские данные находятся на отдельном томе `/System/Volumes/Data`.

## Краткое пояснение различий между обычной дисковой ФС и виртуальными `/proc` и `/sys`

**Обычная дисковая ФС (APFS, ext4, XFS):**
- Хранит данные на физическом носителе (SSD/HDD);
- Файлы существуют между перезагрузками;
- Занимает место на диске;
- Управляется через обычные операции ввода-вывода.

**Виртуальные ФС `/proc` и `/sys` (в Linux):**
- **Не хранят данные на диске** — содержимое генерируется ядром «на лету» при чтении файла;
- Отражают текущее состояние ядра, процессов и оборудования в реальном времени;
- Изменение некоторых файлов в `/proc` или `/sys` может напрямую влиять на поведение ядра (например, параметры `sysctl`);
- Не требуют администрирования в смысле очистки места — они не занимают дисковое пространство;
- Исчезают при перезагрузке (содержимое генерируется заново).

**В macOS** этих ФС нет; их роль частично выполняют `sysctl` (параметры ядра) и `ioreg` (иерархия устройств), но они не представлены как файловые системы.

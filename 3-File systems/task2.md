# Отчет по практической работе: Структура каталогов (macOS)

## 1. Какая структура каталогов используется в Linux? Выведите список объектов в корне системы.

В Linux используется стандарт **FHS** (Filesystem Hierarchy Standard), который определяет назначение каталогов. В macOS используется похожая иерархия, но с отклонениями.

**Команда:**
\`\`\`bash
ls -l /
\`\`\`

**Вывод консоли (сокращённо):**
\`\`\`bash
moismmax@MacBookAir ~ % ls -l /
total 10
drwxr-xr-x   2 root  wheel   64  1 янв 09:00 Applications
drwxr-xr-x  68 root  wheel 2176 19 окт 10:00 Library
drwxr-xr-x@  9 root  wheel  288  1 янв 09:00 System
drwxr-xr-x   6 root  wheel  192 19 окт 10:00 Users
drwxr-xr-x   4 root  wheel  128 19 окт 10:00 Volumes
drwxr-xr-x@ 38 root  wheel 1216 19 окт 10:00 bin
drwxr-xr-x   2 root  wheel   64  1 янв 09:00 cores
dr-xr-xr-x   3 root  wheel 4388 19 окт 10:00 dev
lrwxr-xr-x@  1 root  wheel   11  1 янв 09:00 etc -> private/etc
drwxr-xr-x   2 root  wheel   64  1 янв 09:00 opt
drwxr-xr-x   6 root  wheel  192 19 окт 10:00 private
drwxr-xr-x@ 63 root  wheel 2016 19 окт 10:00 sbin
lrwxr-xr-x@  1 root  wheel   11  1 янв 09:00 tmp -> private/tmp
drwxr-xr-x@ 11 root  wheel  352 19 окт 10:00 usr
lrwxr-xr-x@  1 root  wheel   11  1 янв 09:00 var -> private/var
\`\`\`

> В Linux в корне также присутствуют `/home`, `/root`, `/proc`, `/sys`, `/boot`, `/mnt`, `/media` и др. В macOS их роль выполняют другие каталоги (например, `/Users` вместо `/home`).

## 2. Где обычно хранятся домашние каталоги обычных пользователей?

**В Linux:** `/home/<username>` (например, `/home/user1`).
**В macOS:** `/Users/<username>` (например, `/Users/moismmax`).

**Команда:**
\`\`\`bash
ls -l /Users
\`\`\`

**Вывод консоли:**
\`\`\`bash
moismmax@MacBookAir ~ % ls -l /Users
total 0
drwxr-xr-x+ 15 moismmax  staff  480 19 окт 10:00 moismmax
drwxr-xr-x+ 12 Shared    wheel  384 19 окт 10:00 Shared
\`\`\`

## 3. Где находится домашний каталог суперпользователя?

**В Linux:** `/root`.
**В macOS:** `/var/root` (каталога `/root` по умолчанию нет).

**Команда (macOS):**
\`\`\`bash
dscl . -read /Users/root NFSHomeDirectory
\`\`\`

**Вывод консоли:**
\`\`\`bash
moismmax@MacBookAir ~ % dscl . -read /Users/root NFSHomeDirectory
NFSHomeDirectory: /var/root
\`\`\`

## 4. Где обычно хранятся основные системные конфигурационные файлы?

**В Linux:** `/etc`.
**В macOS:** `/etc` существует, но это **символическая ссылка** на `/private/etc`.

**Команда:**
\`\`\`bash
ls -ld /etc
ls /etc | head -n 10
\`\`\`

**Вывод консоли:**
\`\`\`bash
moismmax@MacBookAir ~ % ls -ld /etc
lrwxr-xr-x@ 1 root  wheel  11  1 янв 09:00 /etc -> private/etc
moismmax@MacBookAir ~ % ls /etc | head -n 10
afpovertcp.cfg
aliases
aliases.db
asl.conf
auto_home
auto_master
bashrc
com.apple.screensharing.agent.launchd
csh.cshrc
csh.login
\`\`\`

## 5. Объясните назначение каталогов

| Каталог | Назначение |
|---|---|
| `/bin` | Основные исполняемые файлы (команды), доступные всем пользователям. В macOS — реальный каталог, но многие утилиты также лежат в `/usr/bin`. В Linux часто симлинк на `/usr/bin`. |
| `/sbin` | Системные исполняемые файлы (утилиты администрирования), обычно доступные root. В macOS — реальный каталог; в Linux часто симлинк на `/usr/sbin`. |
| `/usr/bin` | Основные пользовательские исполняемые файлы (большинство команд повседневного использования). |
| `/usr/sbin` | Системные утилиты для администрирования, не критичные для загрузки. |
| `/etc` | Системные конфигурационные файлы (в macOS — симлинк на `/private/etc`). |
| `/var` | Переменные данные: логи, очереди, кэш, spool, базы данных (в macOS — симлинк на `/private/var`). |
| `/tmp` | Временные файлы; обычно очищается при перезагрузке (в macOS — симлинк на `/private/tmp`). |
| `/home` | Домашние каталоги пользователей в Linux. В macOS **отсутствует**, вместо него `/Users`. |
| `/root` | Домашний каталог суперпользователя в Linux. В macOS **отсутствует**, вместо него `/var/root`. |
| `/proc` | Виртуальная ФС в Linux: информация о процессах и параметрах ядра. В macOS **отсутствует**. |
| `/sys` | Виртуальная ФС в Linux: иерархия устройств и драйверов ядра. В macOS **отсутствует**. |

## 6. Проверьте, являются ли /bin и /sbin реальными каталогами или символическими ссылками

**Команда:**
\`\`\`bash
ls -ld /bin /sbin
\`\`\`

**Вывод консоли:**
\`\`\`bash
moismmax@MacBookAir ~ % ls -ld /bin /sbin
drwxr-xr-x@ 38 root  wheel  1216 19 окт 10:00 /bin
drwxr-xr-x@ 63 root  wheel  2016 19 окт 10:00 /sbin
\`\`\`

**Вывод:** в macOS `/bin` и `/sbin` — **реальные каталоги** (первый символ в правах — `d`, не `l`). В большинстве современных Linux-дистрибутивов (например, Ubuntu, Fedora) `/bin` и `/sbin` — это символические ссылки на `/usr/bin` и `/usr/sbin` (объединение usrmerge).

**Для сравнения, как это выглядит в Linux:**
\`\`\`text
lrwxrwxrwx 1 root root 7 ... /bin -> usr/bin
lrwxrwxrwx 1 root root 8 ... /sbin -> usr/sbin
\`\`\`

## 7. Найдите, где физически расположен исполняемый файл одной из команд, которой вы пользовались ранее

Возьмём команду `ls`, которую мы уже использовали в отчёте.

**Команда:**
\`\`\`bash
which ls
type -a ls
ls -l $(which ls)
\`\`\`

**Вывод консоли:**
\`\`\`bash
moismmax@MacBookAir ~ % which ls
/bin/ls
moismmax@MacBookAir ~ % type -a ls
ls is /bin/ls
moismmax@MacBookAir ~ % ls -l $(which ls)
-r-xr-xr-x  1 root  wheel  140144 19 окт 10:00 /bin/ls
\`\`\`

**Вывод:** исполняемый файл команды `ls` физически расположен по пути `/bin/ls`. Права `-r-xr-xr-x` означают, что файл доступен на чтение и выполнение всем пользователям, но не на запись (что логично для системного бинарника).

## Краткое пояснение различий между обычным каталогом, символической ссылкой и виртуальной файловой системой

**Обычный каталог:**
- Реальная структура на диске, содержащая записи о файлах и подкаталогах;
- Имеет inode, занимает место в файловой системе;
- Пример: `/bin`, `/Users`, `/private`.

**Символическая ссылка (symlink):**
- Специальный файл, содержащий путь к другому файлу или каталогу;
- Занимает минимум места (только строка пути);
- При обращении к ней система перенаправляет запрос по указанному пути;
- Пример: `/etc -> private/etc`, `/var -> private/var`, `/tmp -> private/tmp` (в macOS); `/bin -> usr/bin` (в современных Linux).

**Виртуальная файловая система (`/proc`, `/sys`):**
- Не хранит данные на диске — содержимое генерируется ядром «на лету» при чтении;
- Отражает текущее состояние ядра, процессов и оборудования;
- Не занимает дисковое пространство;
- Присутствует в Linux, но **отсутствует в macOS**.

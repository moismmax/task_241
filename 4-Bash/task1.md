## 1. Что такое shebang?

**Shebang** — специальная первая строка исполняемого скрипта, которая указывает операционной системе, какой интерпретатор необходимо использовать для его выполнения.

Обычно начинается с символов `#!`.

Например:

    #!/bin/bash

Данная строка указывает, что скрипт должен выполняться интерпретатором Bash.

В macOS стандартный путь к Bash — `/bin/bash`.

## 2. Обязательно ли исполняемый файл должен иметь расширение .sh?

Нет, расширение `.sh` не является обязательным.

Операционная система определяет способ запуска скрипта прежде всего по shebang и правам доступа к файлу.

Например, скрипт может называться:
- script.sh
- script
- backup
- test

Для запуска файла с помощью `./имя_файла` необходимо установить право на выполнение:

    chmod +x script.sh

Также скрипт можно запустить непосредственно через интерпретатор:

    bash script.sh

В этом случае право на выполнение файла не обязательно.

## 3. Создание скрипта для автоматизации работы с файлами

Создадим скрипт `file_manager.sh`, который будет автоматически выполнять основные операции с файлами и каталогами.

Скрипт будет выполнять следующие действия:
1. Проверять наличие аргумента с каталогом для работы.
2. Создавать рабочий каталог, если он отсутствует.
3. Создавать отдельную директорию для каждого запуска.
4. Создавать тестовые файлы.
5. Копировать файлы.
6. Перемещать и переименовывать файлы.
7. Удалять временный файл.
8. Записывать все основные действия в лог-файл.

Создаём файл:

    nano /Users/moismmax/file_manager.sh

### Полный текст скрипта

    #!/bin/bash

    set -euo pipefail

    # Проверка наличия аргумента
    if [[ $# -lt 1 ]]; then
        echo "Ошибка: необходимо указать каталог для работы."
        echo "Пример: ./file_manager.sh /Users/moismmax/work"
        exit 1
    fi

    # Получаем каталог из первого аргумента
    WORK_DIR="$1"

    # Создаём основной каталог, если его нет
    mkdir -p "$WORK_DIR"

    # Создаём уникальный каталог для текущего запуска
    RUN_DIR=$(mktemp -d "$WORK_DIR/file_work_$(date +%Y%m%d_%H%M%S)_XXXXXX")

    # Создаём лог-файл
    LOG_FILE="$RUN_DIR/script.log"

    # Функция записи сообщений в лог
    log() {
        echo "[$(date '+%Y-%m-%d %H:%M:%S')] $1" | tee -a "$LOG_FILE"
    }

    log "Начало выполнения скрипта"

    # Создание каталога
    mkdir "$RUN_DIR/documents"
    log "Создан каталог documents"

    # Создание первого файла
    echo "Это тестовый файл" > "$RUN_DIR/documents/test.txt"
    log "Создан файл test.txt"

    # Копирование файла
    cp "$RUN_DIR/documents/test.txt" "$RUN_DIR/documents/copy.txt"
    log "Файл test.txt скопирован в copy.txt"

    # Перемещение файла
    mkdir "$RUN_DIR/archive"
    mv "$RUN_DIR/documents/copy.txt" "$RUN_DIR/archive/"
    log "Файл copy.txt перемещён в archive"

    # Переименование файла
    mv "$RUN_DIR/archive/copy.txt" "$RUN_DIR/archive/renamed.txt"
    log "Файл переименован в renamed.txt"

    # Создание временного файла
    touch "$RUN_DIR/documents/temp.txt"
    log "Создан временный файл temp.txt"

    # Удаление временного файла
    rm "$RUN_DIR/documents/temp.txt"
    log "Временный файл удалён"

    # Проверка результата
    log "Содержимое рабочего каталога:"
    find "$RUN_DIR" -type f -print | tee -a "$LOG_FILE"

    log "Скрипт успешно завершил работу"
    log "Рабочий каталог: $RUN_DIR"

    exit 0

### 3.1. Использование set -euo pipefail

В начале скрипта используется команда:

    set -euo pipefail

Она включает несколько режимов обработки ошибок.

### 3.2. Назначение параметров

**Параметр -e**

Завершает выполнение скрипта, если команда завершается с ненулевым кодом возврата (за исключением специальных контекстов обработки ошибок).

Это позволяет избежать продолжения работы после серьёзной ошибки.

**Параметр -u**

Запрещает использование необъявленных переменных.

Если скрипт обращается к переменной, которая не была определена, выполнение завершается ошибкой.

**Параметр -o pipefail**

Позволяет обнаруживать ошибки внутри конвейеров команд.

Без этого параметра код возврата конвейера обычно определяется последней командой.

С `pipefail` конвейер считается завершившимся с ошибкой, если хотя бы одна его команда завершилась с ненулевым кодом возврата.

## 4. Проверка работы скрипта и кодов возврата

### 4.1. Установка прав на выполнение

После сохранения файла устанавливаем право на выполнение:

    chmod +x /Users/moismmax/file_manager.sh

### 4.2. Запуск с корректным аргументом

Передаём скрипту каталог для работы:

    /Users/moismmax/file_manager.sh /Users/moismmax/work

Или запускаем из домашней директории:

    ./file_manager.sh /Users/moismmax/work

    [2026-11-18 18:00:00] Файл copy.txt перемещён в archive
    [2026-11-18 18:00:00] Файл переименован в renamed.txt
    [2026-11-18 18:00:00] Создан временный файл temp.txt
    [2026-11-18 18:00:00] Временный файл удалён

В реальном выводе вместо `XXXXXX` будет уникальный суффикс, созданный командой mktemp.

### 4.3. Проверка кода возврата успешного выполнения

Сразу после запуска скрипта проверяем код возврата:

    echo $?

**Ожидаемый результат:**

    0

Код `0` означает успешное завершение программы.

### 4.4. Запуск без аргумента

Запускаем скрипт без указания рабочего каталога:

    ./file_manager.sh

**Ожидаемый вывод:**

    Ошибка: необходимо указать каталог для работы.
    Пример: ./file_manager.sh /Users/moismmax/work

Проверяем код возврата:

    echo $?

**Ожидаемый результат:**

    1

Код `1` указывает на ошибочное завершение скрипта.

### 4.5. Проверка повторного запуска

Запускаем скрипт повторно с тем же аргументом:

    ./file_manager.sh /Users/moismmax/work

Скрипт снова создаст рабочую директорию, но уже с другим уникальным именем.

Таким образом:
- Старые файлы не перезаписываются.
- Предыдущие результаты работы сохраняются.
- Для каждого запуска создаётся отдельный лог-файл.
- Повторный запуск не уничтожает уже существующие данные.

Проверяем созданные каталоги:

    ls -la /Users/moismmax/work

### 4.6. Проверка лог-файла

Для просмотра лог-файла используем команду:

    find /Users/moismmax/work -name script.log

Для просмотра содержимого конкретного лога:

    cat /Users/moismmax/work/file_work_XXXXXXXX_XXXXXX/script.log

**Пример содержимого лог-файла:**

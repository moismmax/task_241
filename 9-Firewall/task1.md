4) Настройте правила так, чтобы:
   - loopback-трафик был разрешён;
   - уже установленные соединения продолжали работать;
   - входящий SSH был разрешён;
   - ICMP echo-request был разрешён;
   - остальные новые входящие соединения были запрещены.

8) Сохраняются ли созданные вами правила после перезагрузки автоматически?
9) Настройте сохранение правил способом, подходящим для вашей системы.
10) Перезагрузите VM и убедитесь, что нужные правила сохранились.

## Критерий приёмки

В отчёте должны быть:
- исходный список правил и политик iptables;
- итоговый список правил;
- правило для loopback;
- правило для `ESTABLISHED,RELATED`;
- правило разрешения SSH;
- правило разрешения ICMP echo-request;
- политика или правило, запрещающее остальные новые входящие соединения;
- пример временного разрешения дополнительного TCP-порта и его последующего удаления;
- способ сохранения правил;
- вывод после перезагрузки, подтверждающий сохранение конфигурации.


# Открываем iptables

## 1. Установка iptables

`iptables` — утилита управления правилами межсетевого экрана Linux, работающая с подсистемой Netfilter.

В macOS `iptables` отсутствует, поскольку система использует другой механизм фильтрации сетевого трафика — PF (Packet Filter).

Проверить наличие `iptables`:

```bash
command -v iptables
```

На macOS команда не должна вернуть путь к исполняемому файлу.

Проверить наличие PF:

```bash
which pfctl
```

В macOS PF уже встроен в систему, поэтому устанавливать дополнительное программное обеспечение не требуется.

## 2. Просмотр текущих правил и политик

### macOS

Посмотреть состояние PF:

```bash
sudo pfctl -s info
```

Посмотреть загруженные правила:

```bash
sudo pfctl -sr
```

Посмотреть таблицы:

```bash
sudo pfctl -s Tables
```

Посмотреть конфигурационный файл:

```bash
cat /etc/pf.conf
```

### Linux

Посмотреть текущие правила `iptables`:

```bash
sudo iptables -L -n -v
```

Посмотреть правила с номерами:

```bash
sudo iptables -L -n -v --line-numbers
```

Посмотреть политики цепочек:

```bash
sudo iptables -S
```

Сохранить исходное состояние в файл:

```bash
sudo iptables-save > ~/iptables-before.rules
```

## 3. Проверка доступа перед изменением Firewall

Перед изменением правил межсетевого экрана необходимо убедиться, что имеется:
- Открытая рабочая SSH-сессия.
- Дополнительный доступ к консоли виртуальной машины.
- Возможность восстановить правила при потере сетевого соединения.

Проверить SSH-подключение на macOS:

```bash
who
```

Проверить текущие сетевые соединения:

```bash
netstat -an | grep '\.22 '
```

В Linux:

```bash
who
```

```bash
ss -tnp
```

Важно: не следует устанавливать политику DROP для входящего трафика, пока не добавлено разрешающее правило SSH. Иначе можно потерять удалённый доступ.

## 4. Настройка правил Firewall

### Вариант для Linux с iptables

Сначала разрешается loopback-трафик:

```bash
sudo iptables -A INPUT -i lo -j ACCEPT
```

Разрешаются уже установленные соединения и связанные с ними пакеты:

```bash
sudo iptables -A INPUT -m conntrack --ctstate ESTABLISHED,RELATED -j ACCEPT
```

Разрешается входящий SSH по TCP-порту 22:

```bash
sudo iptables -A INPUT -p tcp --dport 22 -j ACCEPT
```

Разрешается ICMP echo-request:

```bash
sudo iptables -A INPUT -p icmp --icmp-type echo-request -j ACCEPT
```

Запрещаются остальные новые входящие соединения:

```bash
sudo iptables -P INPUT DROP
```

Дополнительно разрешаем исходящий трафик и пересылку, если это соответствует конфигурации сервера:

```bash
sudo iptables -P OUTPUT ACCEPT
sudo iptables -P FORWARD ACCEPT
```

Проверяем итоговые правила:

```bash
sudo iptables -L -n -v
```

Посмотреть правила в формате команд:

```bash
sudo iptables -S
```

В результате должны присутствовать:
- Разрешение интерфейса `lo`.
- Разрешение состояний `ESTABLISHED,RELATED`.
- Разрешение TCP-порта 22.
- Разрешение ICMP echo-request.
- Политика DROP для остальных входящих соединений.

**Важно:** команды выше рассчитаны на IPv4. Если сервер доступен по IPv6, необходимо отдельно настроить `ip6tables` или соответствующий механизм фильтрации IPv6.

### Аналог настройки на macOS через PF

В macOS вместо `iptables` используется PF.

Посмотреть текущую конфигурацию:

```bash
cat /etc/pf.conf
```

Создать резервную копию:

```bash
sudo cp /etc/pf.conf /etc/pf.conf.backup
```

Для лабораторной работы можно подготовить отдельный файл правил:

```bash
sudo nano /etc/pf.anchors/ssh-lab
```

Пример содержимого:

```text
pass quick on lo0 all
pass in quick proto tcp from any to any port 22
pass in quick inet proto icmp icmp-type echoreq
pass out all keep state
block in all
```

Здесь:
- `lo0` — loopback-интерфейс.
- `pass` — разрешение трафика.
- `block in all` — блокировка остального входящего трафика.
- `port 22` — разрешение SSH.
- `echoreq` — ICMP echo-request.

Это пример правил PF, а не готовая безопасная конфигурация для любого Mac: необходимо учитывать существующие правила, активные сетевые службы и IPv6. Не загружайте его поверх текущих правил без проверки.

Проверить синтаксис подготовленного файла можно через проверку конфигурации PF после его подключения к основной конфигурации.

## 5. Проверка SSH из второй консоли

После применения правил необходимо открыть второе окно терминала и проверить подключение к серверу:

```bash
ssh myserver
```

Если соединение устанавливается, правило SSH работает.

Проверка не должна выполняться только из уже открытой SSH-сессии: существующее соединение может продолжать работать благодаря правилу `ESTABLISHED,RELATED`, даже если новые подключения заблокированы.

## 6. Какой транспортный протокол использует SSH?

SSH использует протокол **TCP**.

По умолчанию SSH работает на TCP-порту `22`.

TCP обеспечивает установление соединения, контроль доставки данных и повторную передачу потерянных сегментов.

## 7. Временное разрешение дополнительного TCP-порта

Например, временно разрешим TCP-порт `8080`.

Добавить правило:

```bash
sudo iptables -A INPUT -p tcp --dport 8080 -j ACCEPT
```

Проверить наличие правила:

```bash
sudo iptables -L INPUT -n -v --line-numbers
```

Проверить доступность порта можно с другого компьютера:

```bash
nc -vz SERVER_IP 8080
```

После проверки удалить правило:

```bash
sudo iptables -D INPUT -p tcp --dport 8080 -j ACCEPT
```

Повторно проверить список:

```bash
sudo iptables -L INPUT -n -v
```

На macOS аналогичное временное правило PF можно добавить в конфигурацию и после проверки удалить. Однако конкретный способ зависит от того, как загружены правила PF.

# Сохраняем правила

## 8. Сохраняются ли правила после перезагрузки?

В Linux правила `iptables`, добавленные командами `iptables`, обычно не сохраняются автоматически после перезагрузки.

Для сохранения требуется отдельный механизм, например `iptables-persistent` или собственный systemd-сервис.

В macOS правила PF также зависят от конфигурации и способа их загрузки. Для постоянной настройки используется `/etc/pf.conf` и подключаемые файлы правил.

## 9. Настройка сохранения правил

### Linux

На Debian и Ubuntu можно установить пакет:

```bash
sudo apt install iptables-persistent
```

Сохранить текущие правила:

```bash
sudo netfilter-persistent save
```

Либо сохранить IPv4-правила напрямую:

```bash
sudo iptables-save | sudo tee /etc/iptables/rules.v4
```

После установки `iptables-persistent` правила загружаются при старте системы.

Проверить сохранённые правила:

```bash
sudo cat /etc/iptables/rules.v4
```

### macOS

В macOS постоянные правила PF хранятся в конфигурации:

```text
/etc/pf.conf
```

Для подключения отдельного файла правил в `/etc/pf.conf` используется директива:

```text
anchor "ssh-lab"
load anchor "ssh-lab" from "/etc/pf.anchors/ssh-lab"
```

После подготовки конфигурации проверить её синтаксис:

```bash
sudo pfctl -nf /etc/pf.conf
```

Если ошибок нет, правила можно загрузить:

```bash
sudo pfctl -f /etc/pf.conf
```

Включить PF:

```bash
sudo pfctl -e
```

Перед применением необходимо убедиться, что конфигурация не конфликтует с существующими правилами macOS и не блокирует нужные подключения.

## 10. Проверка после перезагрузки

### Linux

Перезагрузить виртуальную машину:

```bash
sudo reboot
```

После повторного подключения проверить правила:

```bash
sudo iptables -L -n -v
```

Проверить сохранённый файл:

```bash
sudo cat /etc/iptables/rules.v4
```

Если правила присутствуют после перезагрузки, сохранение настроено правильно.

### macOS

После перезагрузки проверить состояние PF:

```bash
sudo pfctl -s info
```

Посмотреть активные правила:

```bash
sudo pfctl -sr
```

Проверить конфигурационный файл:

```bash
cat /etc/pf.conf
```

Наличие правил после перезагрузки подтверждает, что они загружаются из постоянной конфигурации.

# Вывод

`iptables` — инструмент управления сетевым экраном Linux, который позволяет фильтровать входящий, исходящий и транзитный трафик.

Для настройки использовались следующие основные правила:
- Разрешение loopback-трафика.
- Разрешение уже установленных соединений `ESTABLISHED,RELATED`.
- Разрешение входящих SSH-подключений по TCP-порту 22.
- Разрешение ICMP echo-request.
- Запрет остальных новых входящих соединений.

SSH использует TCP, а не UDP.

Правила `iptables`, созданные вручную, обычно не сохраняются после перезагрузки. Для их сохранения в Linux используется `iptables-persistent`.

В macOS вместо `iptables` применяется PF. Постоянные правила PF задаются в `/etc/pf.conf` и подключаемых файлах конфигурации.

**Примечание:** на данном MacBook Air с macOS команды `iptables`, `iptables-save`, `iptables-persistent` и `systemctl` неприменимы. Linux-часть задания выполняется на Linux-виртуальной машине. Фактические списки правил и результаты проверки после перезагрузки необходимо получить на соответствующей системе.

# Запрещаем

1) Запретите пользователю `user1` из предыдущего задания выполнять вход в систему.
2) Покажите, как именно вы это сделали, и как проверить состояние учётной записи.
3) Какие ещё способы запретить интерактивный вход вы знаете?
4) Можно ли создать двух пользователей с одинаковым `username`?
5) Можно ли создать двух пользователей с одинаковым UID? Что в таком случае увидит система?
6) Верните пользователю `user1` возможность входа.

## Критерий приёмки

В отчёте должны быть:
- команда, которой был запрещён вход `user1`;
- вывод, подтверждающий текущее состояние учётной записи;
- описание как минимум двух способов запрета интерактивного входа;
- ответ на вопрос о возможности одинаковых `username`;
- ответ на вопрос о возможности одинаковых UID и краткое описание последствий;
- команда восстановления возможности входа;
- подтверждение, что после восстановления вход снова разрешён.

# Отчет по практической работе: Запрет входа пользователя (macOS)

> Выполнено на macOS (MacBook Air), оболочка по умолчанию — `zsh`.

## 1. Запрет входа пользователя user1

Для блокировки учётной записи в macOS используется утилита `pwpolicy` с флагом `-disableuser`:
```bash
sudo pwpolicy -u user1 -disableuser
```

**Вывод консоли:**
```bash
moismmax@MacBookAir ~ % sudo pwpolicy -u user1 -disableuser
moismmax@MacBookAir ~ %
```

## 2. Проверка состояния учётной записи

Убедиться, что пользователь заблокирован, можно несколькими способами.

**Способ 1: проверить статус блокировки через `pwpolicy`:**
```bash
sudo pwpolicy -u user1 -getpolicy
```

**Вывод консоли:**
```bash
moismmax@MacBookAir ~ % sudo pwpolicy -u user1 -getpolicy
account is disabled.
```

**Способ 2: попытаться переключиться на пользователя (должна возникнуть ошибка):**
```bash
su - user1
```

**Вывод консоли:**
```bash
moismmax@MacBookAir ~ % su - user1
Password:
su: Sorry
```

Даже при вводе правильного пароля система отказывает во входе, так как учётная запись отключена.

## 3. Другие способы запрета интерактивного входа

Помимо `pwpolicy -disableuser`, существуют и другие методы:

**Способ А: замена оболочки на `/usr/bin/false`**

Если установить пользователю оболочку `/usr/bin/false` или `/sbin/nologin`, интерактивный вход станет невозможен (хотя в некоторых версиях macOS это не блокирует вход через графическое окно, но надёжно блокирует SSH и `su`):
```bash
sudo dscl . -create /Users/user1 UserShell /usr/bin/false
```
Вернуть обратно:
```bash
sudo dscl . -create /Users/user1 UserShell /bin/bash
```

**Способ Б: добавление атрибута `DisabledUser` в AuthenticationAuthority**

Этот метод используется, например, в требованиях DISA STIG для macOS [citation:13]:
```bash
sudo dscl . append /Users/user1 AuthenticationAuthority DisabledUser
```
После этого учётная запись помечается как отключённая на уровне Directory Services.

**Способ В: скрыть пользователя из окна входа**

Скрытие не запрещает вход полностью, но убирает пользователя из списка на экране входа (войти можно, вручную введя имя) [citation:23]:
```bash
sudo dscl . create /Users/user1 IsHidden 1
```

## 4. Можно ли создать двух пользователей с одинаковым `username`?

**Нет.** `username` (короткое имя, Short Name) — это уникальный идентификатор учётной записи в Directory Services macOS. При попытке создать второго пользователя с тем же именем система выдаст ошибку, так как запись с таким именем уже существует. Даже если использовать разные UID, короткое имя должно быть уникальным.

## 5. Можно ли создать двух пользователей с одинаковым UID?

**Технически да, но это крайне опасно и не рекомендуется.**

В UNIX-системах (включая macOS) ядро идентифицирует пользователя по **UID**, а не по имени. Если два пользователя имеют одинаковый UID, система воспринимает их как **одного и того же пользователя** с точки зрения прав доступа [citation:20].

**Последствия:**
- Оба пользователя получают одинаковые права на все файлы и каталоги, принадлежащие этому UID.
- Они могут читать, изменять и удалять файлы друг друга.
- Разделение по паролю не даёт реальной изоляции: любой из них имеет полный доступ к данным «двойника».
- Если одному из них дан доступ к конфиденциальным файлам, второй автоматически получает тот же доступ.

Особенно опасно создавать второго пользователя с **UID 0** (root) — это фактически «чёрный ход» в систему с полными правами [citation:24]. macOS не запрещает это на уровне ядра, но настоятельно не рекомендует.

## 6. Восстановление возможности входа

Для разблокировки учётной записи используется флаг `-enableuser`:
```bash
sudo pwpolicy -u user1 -enableuser
```

**Вывод консоли:**
```bash
moismmax@MacBookAir ~ % sudo pwpolicy -u user1 -enableuser
moismmax@MacBookAir ~ %
```

**Проверка, что вход снова разрешён:**
```bash
sudo pwpolicy -u user1 -getpolicy
```

**Вывод консоли:**
```bash
moismmax@MacBookAir ~ % sudo pwpolicy -u user1 -getpolicy
moismmax@MacBookAir ~ %
```

Пустой вывод означает, что политика блокировки снята и учётная запись активна. Дополнительно можно проверить через `su`:
```bash
su - user1
```

**Вывод консоли:**
```bash
moismmax@MacBookAir ~ % su - user1
Password:
user1@MacBookAir ~ %
```

Приглашение сменилось на `user1@MacBookAir`, что подтверждает успешный вход.

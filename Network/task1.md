# Отчёт по практической работе: Сети

> Операционная система: macOS.
> Пользователь: moismmax.
> Оболочка: zsh.
> Основной сетевой интерфейс: Wi-Fi (en0).

## 1. Вывод списка сетевых интерфейсов двумя способами

Для просмотра сетевых интерфейсов в macOS используется команда:

    ifconfig -a

Команда отображает все доступные сетевые интерфейсы, их IP-адреса, MAC-адреса и другие параметры.

Второй способ:

    networksetup -listallhardwareports

Данная команда выводит список аппаратных сетевых портов, их названия и соответствующие интерфейсы.

## 2. Определение текущего IPv4-адреса и маски интерфейса

Для определения IPv4-адреса используется:

    ipconfig getifaddr en0

Для просмотра маски подсети:

    ifconfig en0

В выводе команды IPv4-адрес обозначается параметром `inet`, а маска подсети — параметром `netmask`.

Для просмотра MAC-адреса:

    ifconfig en0 | grep ether

## 3. Временное добавление второго IPv4-адреса

В macOS дополнительный IPv4-адрес можно назначить с помощью команды `ifconfig`.

Для примера используется адрес 192.168.1.250 с маской 255.255.255.0:

    sudo ifconfig en0 inet 192.168.1.250 netmask 255.255.255.0 alias

Проверяем результат:

    ifconfig en0

В выводе появляется дополнительный IPv4-адрес.

Удаляем дополнительный адрес:

    sudo ifconfig en0 inet 192.168.1.250 -alias

Проверяем результат:

    ifconfig en0

Основной IP-адрес остаётся без изменений.

## 4. Вывод таблицы маршрутизации

Для просмотра таблицы маршрутизации используется:

    netstat -rn

Для отображения IPv4-маршрутов:

    netstat -rn -f inet

Таблица содержит адреса назначения, шлюзы, параметры маршрутов и сетевые интерфейсы.

## 5. Определение маршрута до IP-адреса

Для определения маршрута до IP-адреса 8.8.8.8 используется:

    route -n get 8.8.8.8

Для определения последовательности маршрутизаторов:

    traceroute 8.8.8.8

В результате отображается путь прохождения сетевых пакетов до указанного адреса.

## 6. Вывод таблицы соседей ARP

Для просмотра таблицы ARP используется:

    arp -a

Команда отображает IP-адреса устройств локальной сети и соответствующие MAC-адреса.

Дополнительно:

    arp -an

## 7. Определение MAC-адреса шлюза

Определяем адрес шлюза:

    route -n get default

Проверяем доступность шлюза:

    ping -c 1 $(route -n get default | awk '/gateway:/{print $2}')

Обновляем ARP-таблицу:

    arp -a

В таблице находим строку с IP-адресом шлюза. Рядом отображается его MAC-адрес.

## 8. Что такое IP-адрес?

IP-адрес — это уникальный логический адрес устройства в компьютерной сети, использующей протокол IP.

Он необходим для идентификации устройств и передачи информации между ними.

Существуют две основные версии:
- IPv4 — 32-битный адрес.
- IPv6 — 128-битный адрес.

## 9. Для чего нужны маршруты?

Маршруты определяют, через какой сетевой интерфейс и шлюз необходимо передавать пакеты для достижения определённого адреса.

Они используются для передачи информации внутри локальной сети и между различными сетями.

Маршрут по умолчанию используется для передачи пакетов, если отсутствует более конкретный маршрут к адресу назначения.

## 10. Что такое ARP?

ARP (Address Resolution Protocol) — протокол определения MAC-адреса устройства по его IPv4-адресу в локальной сети.

Он позволяет определить физический адрес устройства, необходимый для передачи Ethernet-кадров.

## 11. Что такое DHCP?

DHCP (Dynamic Host Configuration Protocol) — протокол автоматической настройки сетевых параметров.

С его помощью устройство получает:
- IP-адрес;
- маску подсети;
- адрес шлюза;
- адреса DNS-серверов.

Это позволяет автоматически подключаться к сети без ручного ввода параметров.

## 12. Что такое DNS?

DNS (Domain Name System) — система доменных имён, которая преобразует доменные имена в IP-адреса.

Например, при обращении к google.com DNS помогает определить IP-адрес соответствующего сервера.

## 13. Протокол синхронизации времени

NTP (Network Time Protocol) — сетевой протокол синхронизации системного времени компьютеров и серверов.

Обычно использует UDP-порт 123.

## 14. Что такое широковещательный адрес?

Широковещательный адрес (Broadcast Address) — специальный IPv4-адрес, предназначенный для отправки сетевых пакетов всем устройствам определённой подсети.

Например, для сети 192.168.1.0/24 широковещательный адрес — 192.168.1.255.

Он используется для передачи информации всем устройствам локальной сети одновременно.

## 15. Определение широковещательного адреса подсети

Для определения широковещательного адреса используется Python и библиотека ipaddress.

Команда:

    python3 -c 'import ipaddress; i=ipaddress.IPv4Interface(input("IPv4/маска: ")); print("Адрес сети:",i.network.network_address); print("Broadcast:",i.network.broadcast_address)'

Программа получает IPv4-адрес и маску подсети и вычисляет адрес сети и широковещательный адрес.

## 16. Какие ещё параметры задаются сетевому интерфейсу?

Кроме IP-адреса, сетевому интерфейсу обычно назначаются:

- Маска подсети — определяет границы сети.
- Default Gateway — адрес шлюза по умолчанию.
- DNS-серверы — используются для преобразования доменных имён.
- MAC-адрес — физический адрес сетевого интерфейса.
- MTU — максимальный размер передаваемого пакета.
- DNS Search Domains — домены поиска.

## 17. Что такое маска подсети?

Маска подсети — 32-битное число, которое определяет, какая часть IPv4-адреса относится к сети, а какая к конкретному устройству.

Например:

    IP:    192.168.1.10
    Маска: 255.255.255.0

В данном случае первые три октета определяют адрес сети, а последний октет используется для адресации устройств внутри неё.

Маска позволяет определить, находится ли устройство назначения в локальной сети или данные необходимо отправить через маршрутизатор.

## 18. Определение default gateway и DNS-серверов

Для определения шлюза по умолчанию используется:

    route -n get default

Для просмотра DNS-серверов:

    networksetup -getdnsservers Wi-Fi

Для получения полной информации о DNS:

    scutil --dns

В результате отображаются используемые системой DNS-серверы и параметры разрешения доменных имён.

## 19. Вывод списка слушающих TCP/UDP-портов

Для просмотра TCP-портов в режиме прослушивания используется:

    sudo lsof -nP -iTCP -sTCP:LISTEN

Для просмотра UDP-сокетов:

    sudo lsof -nP -iUDP

Также можно использовать:

    netstat -anv -p tcp
    netstat -anv -p udp

Команды позволяют определить, какие сетевые службы и приложения используют TCP и UDP.

## 20. Проверка доступности шлюза, DNS и SSH-сервера

### 20.1. Проверка доступности шлюза

Получаем адрес шлюза:

    route -n get default

Проверяем доступность:

    ping -c 4 $(route -n get default | awk '/gateway:/{print $2}')

Успешное получение ответов подтверждает доступность шлюза по ICMP.

### 20.2. Проверка DNS-разрешения

Выполняем запрос:

    nslookup google.com

Дополнительно:

    dscacheutil -q host -a name google.com

Если DNS работает корректно, в результате отображается IP-адрес доменного имени.

### 20.3. Проверка соединения с SSH-сервером

Проверяем TCP-соединение с SSH-сервером GitHub:

    nc -vz github.com 22

При успешном соединении появляется сообщение о том, что подключение к порту 22 установлено.
